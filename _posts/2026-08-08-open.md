The `:open` pseudo-class matches an element that has both an open and a closed state when it is currently open. It lets CSS respond directly to that state without requiring JavaScript or an author-maintained class.

In HTML, elements that can have an open state include `<details>`, `<dialog>`, `<select>`, and some `<input>` controls. Exactly what “open” means depends on the element: a disclosure may be expanded, a dialog may be displayed, or a form control may be showing its picker.

A minimal example styles a `<details>` summary while the disclosure is expanded:

```html
<style>
  details:open > summary {
    font-weight: bold;
    color: rebeccapurple;
  }
</style>

<details>
  <summary>Deployment notes</summary>
  <p>Restart the application after updating its configuration.</p>
</details>
```

When the user opens the disclosure, the `<details>` element matches `:open`; when they close it, the match stops.

This is similar to selecting `details[open]`, but `:open` expresses the element’s state rather than the presence of a particular HTML attribute. That distinction matters for controls whose open state is not necessarily exposed through an `open` attribute. It also gives authors one consistent selector for styling different kinds of openable elements.

The feature is defined in the Selectors Level 4 specification, which remains a draft rather than a finalized web standard. Its definition is deliberately general: `:open` applies only to elements with distinct open and closed states. It does not provide a way to open an element, nor does it match arbitrary elements merely because they are visible.

The main caveat is browser support. Support can differ across browsers and element types, so check current compatibility data and test the specific controls your interface uses. For critical styling, retain an appropriate fallback—for example, `details[open]` when targeting HTML disclosures. Also remember that some native controls use platform-dependent UI, which can affect when their open state exists and how much of that UI is styleable.

Used progressively, `:open` is useful today because it reduces state-tracking code, makes selectors more semantic, and provides a common way to style native interactive elements while they are active.
