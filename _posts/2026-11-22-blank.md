`:blank` is a CSS pseudo-class for user-input elements whose current value is blank—either an empty string or a value consisting only of white space. It lets CSS respond to an empty form control without relying on JavaScript or conflating the control’s value with its DOM content.

A minimal example looks like this:

```html
<label for="bio">Biography</label>
<textarea id="bio" name="bio"></textarea>
```

```css
textarea:blank {
  background-color: #fffbe6;
  border-color: #c58b00;
}
```

The selector has no arguments: it is `:blank`, not a function. In a conforming implementation, the rule above matches while the textarea’s value is empty or contains only white space. It stops matching after the user enters other content.

This differs from `:empty`. The `:empty` pseudo-class concerns an element’s child nodes; it does not test the current value of a form control. For example, an `<input>` element has no child nodes regardless of whether the user has typed into it, so `input:empty` cannot express “this input currently has no value.” `:blank` is designed for that value-based state.

That makes the feature useful for highlighting controls that have not been filled in, displaying contextual hints, or changing surrounding presentation based on whether a user has entered meaningful text. It can also cover optional fields, where constraint-validation selectors such as `:invalid` may not represent the state you want.

However, `:blank` is defined in the Selectors Level 4 draft rather than a finished Recommendation, and the specification lists it as at-risk. Browser implementation should not be assumed. Check the browsers relevant to your project before depending on it, and treat it as a progressive enhancement unless your support testing shows otherwise.

Also remember that “blank” includes white-space-only values. If an application needs different rules—for example, treating spaces as meaningful or applying domain-specific validation—`:blank` is not a replacement for application logic. It represents only the blank-value state defined by the specification.

For unsupported browsers, keep the form usable without the styling and use existing validation or JavaScript when the distinction is functionally required.
