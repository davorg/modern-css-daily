`::backdrop` is a CSS pseudo-element for styling the area behind an element placed in the browser’s **top layer**. Top-layer elements include modal dialogs and elements displayed fullscreen. Each such element receives its own `::backdrop`, rendered immediately beneath it in the top layer but above the document and any earlier top-layer entries.

The feature is defined in **CSS Positioned Layout Module Level 4**, which is currently an Editor’s Draft rather than a finalized Recommendation.

A common use is dimming the page behind a modal `<dialog>`:

```html
<button id="open-dialog">Open dialog</button>

<dialog id="notice">
  <p>Your changes have been saved.</p>
  <form method="dialog">
    <button>Close</button>
  </form>
</dialog>

<style>
  #notice::backdrop {
    background: rgb(0 0 0 / 0.55);
  }
</style>

<script>
  const dialog = document.querySelector("#notice");
  const openButton = document.querySelector("#open-dialog");

  openButton.addEventListener("click", () => {
    dialog.showModal();
  });
</script>
```

Calling `showModal()` places the dialog in the top layer, making its backdrop relevant. The CSS then gives that backdrop a translucent black background.

This is useful because it works with the browser’s top-layer model. You do not need to create a separate overlay element, size it to the viewport, or negotiate `z-index` values with the rest of the page. The backdrop is associated with its originating top-layer element, so multiple top-layer entries can each have their own backdrop and stacking position.

The pseudo-element is also flexible: the specification does not restrict which CSS properties may be applied to it. However, it does not inherit from any element, and nothing inherits from it, so inherited values from the dialog or surrounding document should not be assumed.

There are several caveats. `::backdrop` only applies to an element while that element is in the top layer; making an ordinary element look modal with `position: fixed` does not give it a backdrop. Styling the backdrop also does not by itself implement opening, closing, focus management, or dismissal behavior. Use the relevant HTML or Web API semantics for those responsibilities.

Finally, support can vary by browser and by the top-layer feature being used. Test the specific combination your application relies on and provide an acceptable fallback when necessary.
