The `lh` unit is a font-relative CSS length representing one computed line height of the element on which it is used. For example, `0.5lh` is half that line height, while `2lh` is twice it.

Unlike `em`, which is based on font size, `lh` follows the element’s `line-height`. This makes it especially useful for spacing that should remain aligned with a text block’s vertical rhythm.

```css
.article {
  font: 1rem/1.5 system-ui;
}

.article p + p {
  margin-block-start: 1rem; /* Fallback */
  margin-block-start: 1lh;
}
```

Here, paragraphs are separated by one line height. If the article’s font size or line height changes, the spacing changes with it—without duplicating the `1.5` ratio in a `calc()` expression or maintaining a separate custom property. The earlier declaration provides a fallback for environments that do not understand `lh`; supported browsers use the later declaration.

The unit is useful today for typographic layouts such as article spacing, captions, callouts, code blocks, and controls that should scale with nearby text. It can also make component styles more portable. A component using `padding-block: 0.5lh`, for example, derives its vertical padding from its own typography rather than from a global spacing assumption.

The specification defines `lh` in CSS Values and Units Module Level 4. That module is still a draft rather than a finalized W3C Recommendation, so details remain subject to the standards process. The feature should not be assigned a single “introduction date”: specifications and browser implementations evolve independently.

There are a few caveats. When `line-height` is `normal`, the specification converts it to an absolute length using metrics from the element’s first available font. Consequently, the result can depend on the selected font and user agent. It also does not measure the visible height of a particular line of text. Fallback fonts, unusually tall inline content, replaced elements, or other line-box contents can make an actual rendered line taller than `1lh`.

Browser and embedded-webview support can also differ. Check the environments your project targets rather than relying on a guessed version or support percentage. For progressive enhancement, place a conventional length before the `lh` declaration, as in the example above.
