The `:modal` pseudo-class selects an element while it is in a state that prevents interaction with elements outside it until that state is dismissed.

A common example is an HTML `<dialog>` opened with `showModal()`. The same dialog opened non-modally with `show()` does not match `:modal`. This lets CSS respond to the browser-managed modal state rather than relying on a class or attribute that JavaScript must keep synchronized.

```html
<button id="open">Delete item</button>

<dialog id="confirm">
  <p>Delete this item?</p>
  <form method="dialog">
    <button value="cancel">Cancel</button>
    <button value="delete">Delete</button>
  </form>
</dialog>

<style>
  dialog:modal {
    border: 2px solid crimson;
    border-radius: 0.5rem;
    padding: 1.5rem;
  }
</style>

<script>
  const dialog = document.querySelector("#confirm");

  document.querySelector("#open").addEventListener("click", () => {
    dialog.showModal();
  });
</script>
```

The syntax is simply `:modal`, without parentheses or arguments. It matches the element that excludes outside interaction—not its ancestors or descendants. Descendants can still be targeted with an ordinary descendant selector, such as `dialog:modal button`.

This is useful because modality is behavioral state, not merely presentation. A class such as `.modal` can indicate what an application intends, but it does not prove that the browser has actually placed the element in a modal state. `:modal` reflects the state managed by the user agent, reducing duplicated state and helping styles remain correct when a dialog opens or closes through different code paths.

The feature is defined in Selectors Level 4. The linked CSS Working Group document is a draft specification rather than a finalized W3C Recommendation, so details remain subject to the standards process.

Browser and embedded web-view support can vary. Check the compatibility requirements of your own project, and avoid making essential dialog behavior depend on this styling hook. In a browser that does not recognize `:modal`, the selector will not apply; the underlying dialog can still work, but it will need suitable default styles. It is also prudent to keep `:modal` rules separate from selector lists containing critical fallback selectors, because an unsupported selector can affect parsing of the whole list.
