The CSS `update` media feature describes how frequently an output device can modify content after it has been rendered. It is defined in Media Queries Level 4, which is a W3C Recommendation.

`update` has three discrete values:

- `none`: The layout cannot be updated after rendering, as with a document printed on paper.
- `slow`: The layout can be updated, but not quickly enough for smooth animation.
- `fast`: The output can update quickly enough for smooth animation, as is typical of many screens.

This lets developers treat animation and other rapidly changing effects as progressive enhancements:

```css
.badge {
  opacity: 1;
}

@media (update: fast) {
  .badge {
    transition: opacity 200ms;
  }

  .badge:hover {
    opacity: 0.7;
  }
}
```

Here, the badge remains fully usable on every output device. A short transition is added only when the device reports that it can update quickly. Devices matching `slow` or `none` retain the static behavior.

This feature is useful because the web is not limited to conventional, continuously refreshed screens. Pages may be presented through printers, low-refresh displays, remote or constrained rendering systems, and other output mechanisms. Testing for `update: fast` avoids assuming that every device can display frequent visual changes effectively.

A baseline-first approach also provides a practical fallback where the media feature is not recognized: keep essential content and interactions outside the query, then add update-dependent effects inside it.

There are important caveats. `update` reports a broad update capability, not a numeric refresh rate or a performance benchmark. It does not tell you whether JavaScript is fast, whether a particular animation will maintain its frame rate, or how much battery an effect may consume. The categories are supplied by the user agent, so do not infer a specific hardware type from them.

It also does not represent the user’s accessibility preferences. Even when `update: fast` matches, motion may still be unwanted. Production interfaces should account separately for user motion preferences and ensure that animation is not required to understand content or complete an interaction.

Finally, browser support should be checked for the environments your project targets; avoid relying on `update` as the only mechanism protecting essential functionality.
