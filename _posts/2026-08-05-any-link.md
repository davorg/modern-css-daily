`:any-link` is a CSS pseudo-class that matches an element if it would match either `:link` or `:visited`. In other words, it selects hyperlinks regardless of whether the browser considers their destination visited.

The feature is defined in Selectors Level 4. The linked specification is a CSS Working Group Editor’s Draft, so it participates in the ongoing standards process rather than representing a feature tied to one precise introduction date.

A minimal example looks like this:

```css
a:any-link {
  color: royalblue;
  text-decoration-thickness: 0.12em;
}

a:any-link:hover {
  text-decoration-style: double;
}
```

This styles every hyperlink represented by an `a` element, whether visited or unvisited. An `a` element without an `href` is not a hyperlink and therefore does not match.

Conceptually, `:any-link` is equivalent to matching `:link` and `:visited` together. That makes it useful whenever the link’s history state is irrelevant. Instead of repeating a declaration block for both states, developers can express the intent directly:

```css
nav a:any-link {
  text-decoration: none;
}
```

This is especially helpful in component styles and design systems. It distinguishes actual links from placeholder or script-oriented `a` elements that lack an `href`, while avoiding dependence on visited state. It can also make selectors easier to read: `a:any-link` communicates “anchors that are hyperlinks” more precisely than a bare `a` selector.

There are a few caveats. First, the meaning of “hyperlink” is determined by the document language. In HTML, elements become links according to HTML’s rules; adding `:any-link` does not turn an element into a link.

Second, `:any-link` does not provide access to browsing history. If you need different presentation for visited and unvisited links, use `:visited` and `:link` separately. Browsers intentionally restrict which styles can reveal visited state for privacy reasons.

Finally, confirm compatibility with the browsers required by your project rather than assuming universal support or relying on an unspecified version threshold. Where necessary, the separate `:link` and `:visited` pseudo-classes express the same two-state coverage.
