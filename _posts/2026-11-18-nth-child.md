The `:nth-child()` pseudo-class selects elements according to their position among their siblings. It is useful for repeating patterns, selecting ranges, and styling specific items without adding classes to the markup.

It accepts an `<An+B>` expression. Starting with `n = 0`, the browser selects sibling positions produced by the expression, using one-based indexing. The keywords `odd` and `even` are convenient alternatives.

```html
<ul class="results">
  <li>Alpha</li>
  <li>Beta</li>
  <li>Gamma</li>
  <li>Delta</li>
</ul>
```

```css
.results > li:nth-child(odd) {
  background: #eee;
}
```

This styles the first and third list items. Other useful forms include:

```css
/* The third child */
.item:nth-child(3) {}

/* Every third child, beginning with the second */
.item:nth-child(3n + 2) {}

/* The first three children */
.item:nth-child(-n + 3) {}
```

Selectors Level 4 also defines an optional `of <selector-list>` clause. This counts only siblings matching that selector list:

```css
.results > :nth-child(2 of li:not([hidden])) {
  font-weight: bold;
}
```

Here, the second non-hidden `li` is selected. This differs from putting the filter outside `:nth-child()`: `li:not([hidden]):nth-child(2)` selects a matching `li` only when it is also the second element child overall.

The feature is especially valuable in component and data-driven interfaces, where the number or state of elements may change. It can create striped rows, highlight an initial group, apply repeating grid patterns, or target a filtered position while keeping HTML focused on structure rather than presentation.

`:nth-child()` is defined by the CSS Selectors specification. The linked Selectors Level 4 document is an Editor’s Draft, so its formal status is that of an actively maintained draft rather than a completed W3C Recommendation.

There are a few caveats. Counting is based on element siblings, not text nodes, and starts at one. Without an `of` clause, all element siblings affect the position—even siblings that do not match the selector before `:nth-child()`. DOM changes can therefore change which elements match. The `of <selector-list>` form is newer than the basic positional syntax, so check compatibility requirements when supporting older browsers or embedded web engines. Also remember that `:nth-child()` does not implicitly group by element type; use an explicit filter or consider `:nth-of-type()` when type-based counting is intended.
