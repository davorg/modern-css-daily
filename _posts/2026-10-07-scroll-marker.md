`::scroll-marker` is a generated pseudo-element that represents a scroll target inside a scroll container. It enables controls such as carousel pagination dots or section indicators without requiring JavaScript to track the currently visible item.

Scroll markers belong to a `::scroll-marker-group` generated by a scroll container. Selecting a marker scrolls its originating element into view. The marker corresponding to the current scroll position matches the `:target-current` pseudo-class, allowing its appearance to change automatically.

Here is a minimal horizontal carousel:

```html
<ul class="carousel">
  <li>First slide</li>
  <li>Second slide</li>
  <li>Third slide</li>
</ul>
```

```css
.carousel {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-marker-group: after;
}

.carousel > li {
  flex: 0 0 100%;
  scroll-snap-align: start;
}

.carousel > li::scroll-marker {
  content: "";
  width: 0.75rem;
  height: 0.75rem;
  border-radius: 50%;
  background: gray;
}

.carousel > li::scroll-marker:target-current {
  background: black;
}

.carousel::scroll-marker-group {
  display: flex;
  justify-content: center;
  gap: 0.5rem;
}
```

`scroll-marker-group: after` causes the container to generate a marker group after itself. Each list item then generates a marker by giving its `::scroll-marker` non-`none` content. The browser collects those markers into the group and updates `:target-current` as the relevant slide changes.

This is useful because a common UI pattern becomes declarative. Authors do not need scroll listeners, intersection calculations, or code that synchronizes pagination state with scrolling. Markers also participate in the browser’s scrolling and focus behavior rather than imitating navigation with generic event handlers. Combined with scroll snapping, they provide a compact foundation for carousels, galleries, and paged content.

There are important caveats. The feature is defined in CSS Overflow Module Level 5, which is an Editor’s Draft rather than a finalized web standard, so details may still change. Browser implementation is not universal; test the browsers relevant to your project and treat the feature as a progressive enhancement. Where navigation controls are essential, provide an appropriate fallback—such as ordinary links—and do not assume generated markers alone satisfy every accessibility requirement. Also ensure that slides remain usable through normal scrolling when marker controls are unavailable.
