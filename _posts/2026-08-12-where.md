`:where()` is a functional pseudo-class defined in CSS Selectors Level 4. It matches elements using any selector in its comma-separated argument list, much like `:is()`. Its distinguishing feature is specificity: `:where()` and every selector inside it contribute zero specificity.

```css
:where(article, section, aside) h2 {
  margin-block-start: 0;
}
```

This rule matches an `h2` inside an `article`, `section`, or `aside`. Its specificity comes only from `h2`; the selectors inside `:where()` add nothing. As a result, a simple rule such as the following can override it without requiring a more elaborate selector:

```css
h2 {
  margin-block-start: 1em;
}
```

That makes `:where()` useful for defaults that should remain easy to customize. A component library, reset, or design system can use it to target elements precisely without creating high-specificity rules that application code must fight later.

For example:

```css
:where(.card, .dialog) :where(h1, h2, h3) {
  line-height: 1.2;
}
```

Although this selector includes several classes and element names, only the parts outside `:where()` would contribute specificity. In this example, there are no such parts, so the entire selector has zero specificity. Normal cascade rules still apply: origin, importance, cascade layers, scope, and source order can all affect which declaration wins.

The argument is a forgiving selector list. If one item is invalid, that item is discarded rather than invalidating the entire list. This is useful when lists contain selectors with differing implementation support, though unsupported selectors still will not match anything.

There are a few caveats. Zero specificity does not mean a rule always loses; it can still win when competing declarations are otherwise ordered in its favor. Conversely, selectors written outside `:where()` still add their normal specificity. Use browser compatibility data and test against the browsers required by your project, especially when maintaining older environments. Where support is uncertain, remember that an unsupported pseudo-class causes the selector containing it not to match, so critical styling may need a fallback.

`:where()` is specified in Selectors Level 4, which remains a CSS Working Group draft rather than a finalized W3C Recommendation. Its low-specificity behavior nevertheless makes it practical today for maintainable CSS, particularly when paired with deliberate cascade layers and simple overrides.
