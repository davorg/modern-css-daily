The CSS `pointer` media feature lets a page adapt to the accuracy of the user’s **primary pointing device**. It is defined in the W3C Media Queries Level 4 Recommendation and uses three keyword values:

- `none`: The primary input mechanism does not include a pointing device.
- `coarse`: The primary pointing device has limited accuracy, as is common with touchscreens.
- `fine`: The primary pointing device can accurately target small areas, as is common with a mouse or stylus.

A practical use is increasing the size and spacing of controls when the primary pointer is coarse:

```css
.button {
  min-width: 2.5rem;
  min-height: 2.5rem;
}

@media (pointer: coarse) {
  .button {
    min-width: 3rem;
    min-height: 3rem;
  }
}
```

This does not identify a particular kind of hardware. For example, `pointer: coarse` does not literally mean “touchscreen,” and `pointer: fine` does not necessarily mean “mouse.” The browser evaluates the accuracy of the primary pointing input and exposes the corresponding value.

That distinction makes `pointer` useful today. Interfaces often need larger hit areas and more spacing for less precise input, while fine pointers may comfortably use denser controls. Media queries allow these adjustments without device detection, user-agent sniffing, or assumptions based on screen size. A large screen may use touch input, and a small device may have a connected mouse, so viewport dimensions alone are not a reliable proxy.

There are important caveats. A device can have multiple input mechanisms, but `pointer` describes only the one the browser considers primary. It does not tell you whether other pointing devices are available. Media Queries Level 4 separately defines `any-pointer` for querying the capabilities of all available pointing devices.

Pointer accuracy also says nothing about hovering. Use the `hover` media feature when hover capability matters rather than inferring it from `pointer: fine`.

Finally, do not use `pointer: fine` as a reason to make essential controls unnecessarily small. Users may have reduced motor control, use browser zoom, or interact through unexpected hardware. Treat the feature as a progressive enhancement signal, keep controls accessible by default, and ensure the interface remains usable when the query does not match or is unavailable.
