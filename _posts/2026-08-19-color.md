The CSS `color()` function lets authors specify a color in an explicit color space instead of relying only on familiar sRGB-oriented formats such as hex or `rgb()`. It is defined in CSS Color Module Level 4, which includes predefined spaces such as `srgb`, `srgb-linear`, `display-p3`, `a98-rgb`, `prophoto-rgb`, `rec2020`, `xyz`, `xyz-d50`, and `xyz-d65`.

The linked specification is a CSS Working Group Editor’s Draft. It is standards-track work, but draft details can still change; there is no need to assign the feature a precise “introduction date.”

A practical example uses Display P3 while retaining an sRGB fallback:

```css
.call-to-action {
  background-color: rgb(255 128 0);
  background-color: color(display-p3 1 0.5 0);
}
```

The function starts with the color-space name, followed by three coordinates. An optional alpha value can follow a slash:

```css
.overlay {
  background-color: color(display-p3 0.2 0.6 0.9 / 0.75);
}
```

This is useful today because modern displays can reproduce colors outside the sRGB gamut. `color(display-p3 …)`, for example, can preserve more saturated colors on suitable hardware while keeping the intended color space explicit. Other predefined spaces are valuable in color-managed workflows, when translating design-system values, or when exchanging colors with graphics and media tools.

There are important caveats. Browser support is not universal, so production CSS should include a conventional fallback before the `color()` declaration. Browsers that do not understand the later declaration will ignore it and retain the earlier value. If conditional styling is needed, feature queries can test whether the syntax is recognized:

```css
@supports (color: color(display-p3 1 0.5 0)) {
  /* Styles using color() */
}
```

Parsing support does not guarantee that a device can physically display the requested gamut. The browser may need to map an out-of-gamut color to something the screen can reproduce, so the visible result can vary with the display and color-management pipeline. Authors should also avoid assuming that identical numeric coordinates represent the same visible color across different spaces: each space defines those coordinates differently.

Use `color()` as a progressive enhancement, test on representative displays, and keep accessible contrast requirements in mind rather than relying on saturation alone.
