`font-tech()` is a CSS feature query for testing whether a user agent supports a particular font technology. It is used as an `@supports` condition, allowing stylesheets to progressively enhance typography without assuming that every browser can render the same kind of font.

For example, a site can use a conventional font stack by default and select a COLRv1 color font when that technology is supported:

```css
.hero {
  font-family: system-ui, sans-serif;
}

@supports font-tech(color-COLRv1) {
  .hero {
    font-family: "Brand Color Font", system-ui, sans-serif;
  }
}
```

The condition evaluates according to whether the user agent supports the named technology—in this case, COLRv1 color fonts. If the condition is not true, the rules inside the block do not apply, and the original fallback remains in place.

This is useful because font capabilities are not adequately represented by ordinary CSS declaration tests. A browser might recognize `font-family`, for example, while lacking support for the technology used internally by a particular font. `font-tech()` lets developers test that more specific capability before opting into related design choices.

That makes it especially suitable for progressive enhancement. A design can remain readable with a standard font while enabling richer color-font presentation where available. Because unsupported `@supports` conditions do not activate their enclosed rules, the baseline experience does not need to depend on the query succeeding.

The feature is defined in the draft CSS Conditional Rules Module Level 5 specification. It is not a finalized CSS Recommendation, so its definition and implementations may still evolve. Browser support should be checked against current documentation and tested in the browsers relevant to a project; do not assume that support is universal.

There are also limits to what the query tells you. A true result means the user agent supports the requested font technology. It does not confirm that a particular font is installed, downloaded successfully, contains the required glyphs, or will render identically across platforms. Font loading, fallback behavior, and actual visual output still need separate testing.

In practice, treat `font-tech()` as a capability gate rather than a complete font-validation mechanism: establish a robust fallback first, then use the query to enable technology-specific typography.
