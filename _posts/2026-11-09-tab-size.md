The CSS `tab-size` property controls the spacing used when rendering tab characters (`U+0009`). Rather than replacing a tab with a fixed number of spaces, the browser advances the text to the next regularly spaced tab stop.

`tab-size` is defined in CSS Text Module Level 3, a CSS Working Group specification on the standards track. It has an initial value of `8` and is inherited, so setting it on a block container affects tabs within its descendants.

A typical use is formatting source code:

```css
pre {
  white-space: pre;
  tab-size: 4;
}
```

Here, preserved tab characters advance to tab stops based on four times the advance width of the space character. The specification also permits a non-negative length, such as `2rem`, which sets the distance between tab stops directly.

The distinction between tab stops and spaces matters. A tab does not always occupy the same visible width: it moves from the current position to the next tab stop. Consequently, two tabs can produce different advances depending on the text before them.

This property is useful for code samples, logs, terminal-style output, and other preformatted content. Projects often use tabs for indentation but disagree about whether one tab should appear as two, four, or eight spaces. With `tab-size`, a site can choose a visual convention without modifying the underlying text. Authors can also expose the value as a user preference in documentation or code-viewing interfaces.

There are some caveats. Tabs must survive whitespace processing for `tab-size` to have a visible effect. In ordinary collapsed text, tabs are generally processed like other collapsible whitespace, so the property is most relevant alongside whitespace-preserving behavior such as `white-space: pre` or on elements like `<pre>` whose user-agent styling normally preserves whitespace.

A unitless value depends on the font’s space advance, so results can vary when fonts change. A length gives a more explicit interval, but it still defines tab stops rather than a fixed width for every tab character. Because the property is inherited and applies to block containers, setting it on the relevant preformatted container is usually clearer than applying it broadly.

Finally, standards syntax does not guarantee identical behavior in every browser or rendering context. Test the property in the browsers your project supports, especially when font metrics and exact alignment are important.
