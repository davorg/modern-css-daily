CSS `cap` is a font-relative length unit based on the height of capital letters. `1cap` equals the used cap height of the first available font for an element. Cap height is the font’s nominal height for uppercase letters.

Unlike `1em`, which is tied to the font size and its em square, `1cap` reflects a typographic measurement that more closely corresponds to visible capital letters. It can be used anywhere a CSS `<length>` is accepted.

A minimal example sizes an inline icon to the surrounding text’s cap height:

```css
.label-icon {
  inline-size: 1cap;
  block-size: 1cap;
}
```

This is useful for icons, badges, decorative rules, and other elements that should visually match uppercase text. An icon sized to `1em` can appear too large or too small because the proportion between the em square and capital letters varies among typefaces. Using `1cap` lets the selected font supply that relationship instead of relying on a hard-coded adjustment.

Because `cap` is font-relative, the resulting length responds when the font changes. That can make components more resilient across themes, custom fonts, and fallback fonts. It is especially helpful in reusable design-system components where assuming one typeface’s metrics would be fragile.

The unit is defined in CSS Values and Units Module Level 4. That specification is still a draft rather than a completed Recommendation, so details can continue to evolve. Check current compatibility information and test the browsers and embedded webviews your project supports rather than assuming universal availability.

For a simple fallback, place an established unit before the `cap` declaration:

```css
.label-icon {
  inline-size: 0.7em;
  block-size: 0.7em;
  inline-size: 1cap;
  block-size: 1cap;
}
```

Browsers that do not understand `cap` can retain the earlier declarations.

There are also typographic caveats. Cap height is a font metric, not the exact bounding box of every uppercase glyph. Different letters may extend above or below it, and mixed-font text does not produce a separate `cap` value for every glyph run: the unit uses the first available font. Font loading or fallback selection can therefore change the computed physical size.
