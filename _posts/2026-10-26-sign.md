CSS `sign()` reduces a numeric calculation to its sign. It returns `-1` for a negative value, `1` for a positive value, and `0` for zero. The result is a unitless `<number>`, making it useful as a multiplier in other CSS calculations.

The current syntax is:

```css
sign(<calc-sum>)
```

For example, a component can use one custom property to control its direction:

```css
.arrow {
  --direction: -1;

  transform: scaleX(1);
  transform: scaleX(sign(var(--direction)));
}
```

With `--direction: -1`, the arrow is flipped horizontally. Changing the property to any positive number restores the positive orientation, while `0` collapses it horizontally. The first `transform` declaration is a fallback for browsers that do not recognize `sign()`.

This is especially useful when the magnitude of a value does not matter—only whether it is positive, negative, or zero. A signed custom property can control directional transforms, choose the direction of an offset, or normalize a calculation to one of three states. That can reduce duplicated selectors and avoid passing a separate boolean-like custom property alongside the value that already determines direction.

For example, if a component calculates an offset elsewhere, `sign()` can turn that offset into a unitless direction multiplier. Because its argument is a `<calc-sum>`, it can operate on a calculation rather than only on a literal number.

`sign()` is defined in CSS Values and Units Level 4. That specification is still a draft, so its presence in the specification should not be treated as proof of universal browser interoperability. Before relying on it in production, check current compatibility information and test the browsers relevant to your project. Use a preceding fallback declaration when the enhanced declaration can safely be ignored.

There are also behavioral details to consider. Zero produces zero rather than choosing either direction, which may collapse a scale or remove an offset when the result is used as a multiplier. Custom properties must also substitute to a valid numeric calculation; an invalid value can invalidate the declaration that uses it.

Used with progressive enhancement, `sign()` provides a compact, declarative way to derive direction directly from CSS data instead of duplicating state.
