`:defined` is a CSS pseudo-class that matches elements the user agent considers *defined*. This includes built-in elements such as `<button>` and `<article>`, along with custom elements whose definitions have been registered.

It is especially useful with Web Components. Before JavaScript registers a custom element, the browser may render its contents using default styling. Once the definition is registered, `:defined` starts matching, allowing CSS to distinguish the unresolved state from the defined state.

`:defined` takes no arguments. It can also be combined with `:not()` to target elements that have not yet been defined:

```html
<style>
  status-card:not(:defined) {
    visibility: hidden;
  }

  status-card:defined {
    visibility: visible;
  }
</style>

<status-card>Ready</status-card>

<script>
  customElements.define(
    "status-card",
    class extends HTMLElement {}
  );
</script>
```

In this example, `<status-card>` remains hidden until its custom-element definition is registered. Existing matching elements are then eligible for upgrade, and the `:defined` rule applies.

This can help prevent a flash of unstyled custom-element content while component code is loading. It can also support deliberate placeholder styles:

```css
product-card:not(:defined) {
  opacity: 0.5;
}
```

The feature is specified in CSS Selectors Level 4. The linked CSSWG document is an Editor’s Draft, so it should be treated as an evolving standards document rather than a final Recommendation.

There are several caveats. First, `:defined` is primarily useful for custom elements: ordinary built-in HTML elements are already defined and therefore match it. Second, “defined” does not necessarily mean that a component has finished fetching data, rendering asynchronous content, or completing application-specific initialization. Components should expose a separate state—such as a class or attribute—when those distinctions matter.

Be careful when hiding undefined elements. If JavaScript fails to load or registration never occurs, content hidden with `:not(:defined)` may remain inaccessible. Consider whether readable fallback content is preferable, and place critical styles early enough to avoid an initial flash.

Finally, browser support should be checked against the requirements of your project and tested in target browsers rather than inferred from the specification’s status.
