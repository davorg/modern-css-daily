The CSS `scale` property resizes an element as an independent transform. Unlike `scale()` inside the `transform` property, it can be changed without rebuilding a combined transform string containing translation, rotation, or other transform functions.

`scale` is defined in CSS Transforms Module Level 2. The linked specification is an Editor’s Draft, so details may continue to evolve; it should not be treated as a finalized Recommendation.

A minimal use case is enlarging an interactive element:

```css
.card {
  scale: 1;
  transition: scale 180ms ease;
}

.card:hover {
  scale: 1.05;
}
```

The property accepts `none` or one to three `<number-percentage>` values. With one value, the same scale is used for the X and Y axes. With two values, X and Y are specified separately. A third value specifies scaling on the Z axis. For example:

```css
.example {
  scale: 1.2 0.9;
}
```

Percentages are also valid, with `100%` representing a scale factor of `1`.

The main benefit is independent composition. You can declare `translate`, `rotate`, and `scale` separately, making each operation easier to read, animate, and update. This is particularly useful in component styles, interaction states, and animations where one rule controls movement while another controls size.

When individual transform properties are combined, CSS applies them in the order `translate`, `rotate`, then `scale`, before applying the value of the `transform` property. This fixed order is important when mixing the APIs.

There are several caveats. Scaling changes an element’s rendered appearance but does not make surrounding layout reflow to accommodate its new visual size. The effect also uses `transform-origin`, so the chosen origin affects where the element appears to grow or shrink from. The property applies only to transformable elements.

Finally, support for the traditional `transform` property does not automatically imply support for the individual `scale` property. Check the browser and embedded-webview matrix relevant to your project. Where necessary, use `@supports (scale: 1)` to provide an alternative based on `transform: scale(...)`. Take care when doing so: `scale` and `transform` can both apply, potentially producing an unintended combined transformation.
