`oklch()` is a CSS color function for expressing colors in the cylindrical form of the Oklab color space. It is defined in CSS Color Module Level 4, which is maintained as a CSS Working Group Editor’s Draft. As draft work, it may still receive clarifications or changes; there is no need to assign it a single “introduction date.”

The function has three main components:

- **Lightness** (`L`): how light or dark the color is. `0%` corresponds to black and `100%` to white.
- **Chroma** (`C`): the color’s intensity. Zero produces a neutral gray.
- **Hue** (`H`): an angle around the color wheel.

An optional alpha value follows a slash. The current syntax is space-separated rather than comma-separated:

```css
.accent {
  color: #005fcc;
  color: oklch(58% 0.18 250 / 90%);
}
```

The hexadecimal declaration provides a fallback. A browser that understands `oklch()` uses the later declaration; one that does not will discard it and retain the earlier color.

The main advantage of OKLCH is that it is designed around perceptual lightness. Compared with color models such as HSL, adjustments to lightness and chroma tend to produce more visually consistent results across different hues. That makes OKLCH useful for building palettes, generating hover and active states, and creating design tokens whose relationships are easier to reason about.

For example, related colors can keep the same hue and chroma while changing only lightness. Chroma can also be adjusted separately to make a color more or less vivid. OKLCH can represent colors outside the sRGB gamut, allowing capable displays and browsers to use a wider range of colors.

There are caveats. Browser support should still be checked against the requirements of a particular project, and fallbacks may be necessary for older clients. Not every OKLCH value can be displayed on every screen: available gamut depends on the output device, and browsers may map an out-of-gamut color to one that can be shown. The maximum usable chroma also varies with lightness and hue.

Finally, perceptual uniformity is an improvement, not a guarantee of accessible contrast. Always test foreground and background combinations rather than assuming that a particular lightness difference is sufficient.
