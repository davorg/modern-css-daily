CSS `random()` produces a random numeric value within a specified range. It can be used anywhere CSS accepts a compatible numeric type, such as a length, angle, time, percentage, or unitless number.

The function is defined in the Editor’s Draft of CSS Values and Units Level 5. It remains an experimental feature rather than a universally available part of the web platform, so check current browser support before relying on it.

A minimal example is:

```css
.card {
  width: 16rem;
  width: random(12rem, 20rem);
}
```

The first declaration is a fallback. A browser that does not recognize `random()` will discard the second declaration and keep `width: 16rem`. A supporting browser can choose a width between the two bounds.

The arguments must make sense for the property and be type-compatible. The specification also allows an optional third numeric argument to constrain results to steps. More advanced options control how generated values are shared or cached, but the two-bound form is enough for many progressive-enhancement uses.

`random()` is especially useful for decorative variation. It can vary sizes, positions, rotations, colors, animation delays, or other visual details without generating inline styles or running JavaScript. For example, a collection of decorative particles could receive varied dimensions, while a set of cards could use slightly different rotations to create a less mechanical layout. Keeping this variation in CSS also lets it remain close to the styles it affects.

There are important caveats. Support is not uniform, and the specification may still change. Always provide a sensible fallback when the randomized value affects presentation, and do not make essential content or controls depend on it.

Also, `random()` is not an animation mechanism: authors should not assume that it continuously produces new values or rerolls on every style recalculation. Its results follow the specification’s value-sharing and caching rules. Test the exact behavior your design needs.

Random variation can also harm usability. Large changes may cause layout shifts, obscure content, create inconsistent hit targets, or make debugging and visual regression testing harder. Randomized animation timing should respect reduced-motion preferences. Finally, CSS randomness is for presentation—not security-sensitive identifiers, lotteries, or other decisions requiring cryptographic or auditable randomness.
